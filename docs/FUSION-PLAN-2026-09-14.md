## A. 门禁与信任链（优先级最高）

### A1 · apply 移出工具面 —— 来源：伊

**现状**：本插件 `novel_propose` 的 action 是 `['propose','list','apply','prune']`，全在工具面。模型可以自己 propose、自己 apply，一条龙写完。

**融合做法**：工具面只留 `propose` / `list`。`apply` 与 `prune` 改成面板按钮 → REST 端点（`POST /projects/:id/proposals/:pid/apply`），只有浏览器能调。

**好处**：
- 批准钥匙**物理上**回到用户手里 —— 不靠 persona 自觉
- 模型想改已存章节，只能出提案，用户点「应用」才生效
- 与已有的 `novel_propose` 基建无缝，只差摘参数 + 加端点

**为什么这条排第一**：伊为此把整个数据层重写成 SQLite + 提案队列，我们只需动一个 enum。

### A2 · 审计加 `actor` 字段 —— 来源：鱼

**现状**：本插件 `approvals.outline[n] = true` 是个布尔值，事后无法回答「这是谁批的」。

**鱼的做法**（`workflow/types.ts`）：
```ts
interface AuditEvent {
  seq: number; at: string;
  action: 'enter'|'submit'|'reopen'|'skip'|'force'|'rollback'|'create';
  phase: PhaseId;
  actor: 'user' | 'agent' | 'system';   // ← 关键
  detail: string;
}
```

**融合做法**：`audit.jsonl` 每条事件加 `actor`。模型调工具记 `agent`，REST/面板触发记 `user`，系统自动推进记 `system`。A1 做完后，`apply` 事件必然记 `user`。

**好处**：能直接查「这本书的细纲是模型自己批的还是仙尊批的」——这正是上次诊断「一口气写到底」时缺的证据链。诊断成本从「翻 session 日志」降到「grep 一行」。

### A3 + A4 · 质量判定归代码 —— 来源：彼

**彼的做法**（`lib/index.js`）：`computeGate()` **纯函数**解析「看护卡」的必写场景与禁止项，输出：

| 指标 | 含义 |
|---|---|
| `coverage` | 必写场景覆盖率 |
| `drift` | 偏离度 |
| `missedScenes` | 漏写的场景 |
| `bannedHits` | 命中的禁止项 |
| `passed` | 是否放行 |

`novel_gate_check` 干跑不落盘，保存时才 `gateCheck` 落盘到 `meta.chapters[n].gate`（带时间戳）。

**融合做法**：本插件 `novel_audit` 现在是把材料交给模型让它评。改成**先跑代码算硬指标，再让模型补充主观项**，报告分两段：「机械指标（代码算）」+「审读意见（模型出）」。

**好处**：
- 场景覆盖率/偏离度这类**不需要 LLM** 的判定，零 token、可单测、结果稳定
- 模型不再「既当运动员又当裁判」
- 指标落盘后能看趋势（第 10 章 coverage 95%，第 30 章掉到 60% → 结构松了）

### A5 · gate 默认开 —— 来源：文

**文的现状**：`novel_continue` / `novel_draft` 带 `gate` 参数，写完跑四维阻断质检（事实矛盾/违背承诺书/欠账未回应/物理硬伤）后**自动修复一轮再落盘**—— 但 **默认 `false`**。

**融合做法**：本插件 `novel_write_chapter` 已有 `lib/gate.js`（阶段门禁，管流程）。再加一层**内容门禁**，且**默认开启**（新书前 3 章尤其）。结果写进章节元数据。

**好处**：门禁默认关等于不设防 —— 文的最大问题是「有金刚钻但不用」。我们把默认值反过来。

## B. 一致性校验（零 LLM，性价比最高）

### B1 · `validateContinuity` 全套 —— 来源：室

**室的做法**（`src/core/continuity.ts`，纯函数）：

| 校验项 | 严重度 |
|---|---|
| 人物关系指向已删除/不存在的端点 | error |
| 关系自指 | warning |
| 时间点关联章节已失效 | warning |
| 状态变化找不到人物/关系 | error |
| **死亡人物在后续章节再次出现** | warning |
| 场景参与人物已被删除 | error |
| 人物同时被设为「出场」与「隐藏」 | warning |
| **死亡人物被安排进入当前场景** | error |

`flashback` / `dream` 叙事模式自动豁免。

**融合做法**：抄成 `lib/continuity.js`，`novel_audit` 与面板都调它。

**好处**：
- 「死人在第 30 章又说话了」这类**长篇最常见的硬伤**，自动抓
- 纯函数，不花 token，能写单测
- 七家里只有室做到这一层，其余全靠模型自己记得

### B2 · 角色状态时间线推演 —— 来源：室

**室的做法**：`effectiveCharacterStatusAtChapter(project, charId, n)` —— 从 `initialStatus` 出发，按 `milestone.order` 累加所有 `field === 'status'` 的变化，算出**第 n 章时该角色是死是活**。不是读一个静态字段。

**融合做法**：本插件 `novel_ledger` 已有时间锚。加上「状态变化事件」的记录与推演。

**好处**：角色「第 12 章断腿、第 40 章还能跑」这类错误能算出来。静态字段方案永远做不到。

### B3 · 场景契约 + hidden 人物 —— 来源：室

**室的做法**：`buildWritingContextPlan` 按场景契约挑注入内容 —— `participantIds` 只喂出场人物，`hiddenCharacterIds` 里的人物 **AI 完全看不到**；世界观按标题/标签命中正文才注入（上限 6）；时间线只留相关者近 10 条。

**融合做法**：写章前让用户/模型选「本章出场人物」，其余不注入；支持标记「隐藏人物」。

**好处**：
- **省 token**：现在全书注入，30 章后上下文爆炸
- **悬念保护**：反派身份、幕后黑手在揭晓前不进上下文，模型就没法「不小心写漏」
- 七家里唯一做到场景级上下文裁剪的

## C. 写作质量

### C1 · autoproof 保守三原则 —— 来源：文

**文的做法**（`lib/autoproof.js`）：
1. 只改**唯一匹配**（`count === 1`）的片段
2. `replace` 长度不得超过 `find` 的 2 倍 + 2
3. **高危易混字黑名单**：`恨 戍 戌 柝 祗 祇 菅 圮` —— 若 replace 引入了 find 里没有的这些字，判定为**校对模型自己写错**，跳过
4. 首行（章节标题）不参与替换
5. 「可议项」（重复意象、低效比喻）只写报告，**绝不代改**

**融合做法**：抄进 `novel_polish`。

**好处**：本插件现在没有这层保护 —— 模型说「这里错了要改成 X」，如果 X 本身是错的，就写进去了。这三条是最低成本的防呆。

### C2 · 硬关卡四维质检 —— 来源：文

**文的 gate 四维**：①事实矛盾（数字/时间/信息来源与正文自洽）②违背故事承诺书 ③上一章欠账未回应 ④物理/视角硬伤（人物位置/光线/道具状态/时间锚）。输出 `{"blocking": true/false, "issues": [...]}`，有问题**自动修复一轮再落盘**。

**融合做法**：并入 A5 的内容门禁。

**好处**：本插件有 `novel_briefing`（故事承诺书），但**没有任何机制检查正文是否违背它**。承诺书写了就没人看 —— 这是「故事跑偏」的根因之一。

### C3 · 追读力约束 —— 来源：文

**文的硬约束**（注入到每次写作上下文）：*「上一章欠账未回应前，本章不许开新钩子；每 600–900 字给一次微兑现」*

**融合做法**：本插件 `novel_ledger` 已记钩子/爽点/欠账。把这条**写成注入文本**，并在 C2 的质检里检查「欠账是否回应」。

**好处**：网文的追读率主要靠「承诺→兑现」的节奏。这条把节奏从「凭感觉」变成「有账本、有检查」。

### C4 + C5 · 平台审稿 + 敏感自查 —— 来源：文

**文的做法**：
- `novel_market`：**起点**（黄金三章/单章字数/每 3 章爽点/章末钩子/均订逻辑）+ **番茄**（第 1000 字小爽点/前 3 章打脸/完读率/憋屈时长）双平台审稿
- `novel_censor`：六类 + 红线自查（涉政/色情擦边/暴力/赌博毒品/封建迷信/现实机构影射/未成年红线）

**融合做法**：并入 `novel_audit` 作为可选维度。

**好处**：本插件现在的审校是「通用质量」，没有平台视角。要发网文，**平台口味差异极大**（起点吃长线伏笔，番茄吃前 1000 字爽点），这张体检表能直接指导改稿。敏感自查则是发书前的安全网。

## D. 旁路直调（成本最高，收益也最高）

### D1 + D2 · 独立 key + 并发 —— 来源：文

**文的做法**（`lib/engine.js`）：用独立 `DSH_WRITING_API_KEY` 直连 `api.deepseek.com/chat/completions`，按 `keyRole`（polish / draft / sync / agent）分**四通道**；`novel_batch` 用 worker 池 `Promise.all` **并发起草多章**（`concurrency` 参数）。

鱼也走这条路（`captureRoute` 监听 `llm/stream` 捕获主模型路由后自己调）。

**融合做法**：本插件加一个旁路 engine，**先只在 `/polish` 和 `/proofread` 两个内部工序试点**，不动主写作链路。

**好处**：
- **省主上下文**：校对/蒸馏这类「内部工序」不占用主对话窗口，也不污染历史
- **可并发**：多章草稿并行生成，长篇小说总耗时大幅下降
- **省主额度**：独立 key 分流

**为什么放 D 组**：要用户配 key、处理流式与错误、独立计费 —— 是本方案唯一的重资产项，建议 PoC 验证后再全量。

## E. 多代理分工

### E1 + E2 · 队长 + 5 子代理 + 否决权/熔断权 —— 来源：核

**核的做法**（`agent.cordis.yml`）：1 个「统筹队长」不写稿，只派单给 5 个专职子代理（世界 / 剧情 / 人物 / 文笔 / 复核）。三条全局铁律：

1. **通信经济**：派单只给「它需要的切片」，禁止倾倒全量文件；用文件引用代替复述长文本
2. **否决权**：复核实心红灯有**一票驳回权**；意见冲突由队长 3 轮内强制终裁
3. **熔断权**：同一章被连续驳回 3 次 → 召集全体**重新校准《叙事宪法》**，而不是硬压

工作流：逐章循环（文笔写 → 复核把关 → 通过则下一章，红灯则带意见重写）+ 每 3–5 章全局刷新（世界+剧情+人物复盘校准大纲）。

**融合做法**：本插件已有 preset 机制。把这套角色分工写进 preset 的 persona，配 `novel_character` / `novel_outline` / `novel_write_chapter` / `novel_audit` 作为各角色的工具面。

**好处**：
- **单角色职责清晰**：写正文的不管设定，管设定的不写正文 —— 减少「一人分饰多角」导致的顾此失彼
- **否决权让质检有牙齿**：现在 `novel_audit` 出的问题，模型可以选择忽略继续写
- **熔断权治本**：连续调不好说明设定本身有问题，回去改设定而不是硬改文字
- 核只用了 278 行代码就实现这套 —— 是**纯 persona 工程**，我们照抄成本极低

### E3 · 语言基因卡 / 灵魂四维 —— 来源：核

**核的做法**：每个角色建：
- **灵魂四维 JSON**：外在底色 / 隐性欲望 / 心理阈值（弧光触发器）/ 社交关系网
- **语言基因卡**：句子长短 / 逻辑风格 / 口头禅 / 禁忌词 / 标志性小动作

核的理念：**拒绝贴标签**（好人/坏人/高冷/温柔一律不用）；人物是动态的，档案写的只是「起点」不是「终点」；每章写完后做**增量更新**并标注变化依据（引用原文第几段）。

**融合做法**：扩充 `novel_character` 的字段。

**好处**：本插件现在的角色卡偏「设定」（姓名/身份/关系），缺「怎么说话」。有了禁忌词和口头禅，多角色对话不会「千人一腔」——这是 AI 小说最容易被读者看穿的地方。

## F. 流程

### F1 · 九阶段状态机 —— 来源：鱼

**鱼的阶段链**：`topic → setting → character → outline → volume → chapter → writing → revision → done`

每阶段状态：`locked / in_progress / review / approved / skipped`；每阶段带 `PhaseReport`（passed / errorCount / warningCount）；审计事件含 `enter/submit/reopen/skip/force/rollback/create`。

**融合做法**：本插件 `lib/gate.js` 已有 `planning/outline/drafting/revising/done` 五阶段，扩成鱼的九阶段并补 `PhaseReport`。

**好处**：现在的阶段门只查「细纲批没批」。九阶段能把「设定没定就想写大纲」「大纲没过就想写正文」都拦住，且每阶段的校验报告能追溯。

### F2 · 每章申请许可铁律 —— 来源：核

**核的铁律**（persona 原文）：*「每章动笔前向用户申请许可，不擅自连写多章」*

**融合做法**：写进本插件 persona（配合 A5 的内容门禁与 A1 的批准钥匙）。

**好处**：直接治「一口气写到底」。**注意**：这是六家里**唯一**在原则上写死这条的 —— 鱼/文/彼/室/伊 都在代码层没拦。所以 A1（工具层）+ F2（persona 层）是双保险。

## G. 检索与语料

### G1 · SQLite 向量索引 —— 来源：文

**文的做法**：`sqlite-index.js` + `embed-manager.js`，工具 `novel_embed`（建索引）/ `novel_semantic` / `novel_vsearch`。

**融合做法**：本插件 `novel_search` 现在是关键词匹配。加语义检索（可先做可选的本地 embedding，不一定上云）。

**好处**：写第 80 章时要找「第 12 章那个戴斗笠的人说过什么」，关键词匹配找不到，语义检索能找到。**长篇必备**。

### G2 · 书库饲料区 —— 来源：文

**文的做法**：`novel_library_import/list/read/search/analyze/delete` —— 导入外部小说当「饲料」，可检索、可分析。

**融合做法**：新增书库目录 + 对应工具。

**好处**：拆解对标作品的结构（节奏分布、爽点间隔、章节长度曲线），从「凭感觉学」变成「有数据参照」。

## H. 数据完整性

### H1 · SHA-256 revision 乐观并发 —— 来源：伊

**伊的做法**：每个资产的内容哈希是唯一并发输入。写入带 `baseRevision`（上次读到的哈希），不匹配返回 `STALE_REVISION`。persona 强调 *"never retype baseText into tool arguments"* —— 模型不重打旧文本，避免复制错误。

**好处**：面板开着、模型同时在改时，防止互相覆盖。

### H2 · 事件哈希链 —— 来源：室

**室的做法**：`hashEvent(previousHash, type, occurredAt, payload)` —— 每条审计事件链上前一条的哈希。

**好处**：审计日志不可静默篡改。对单人写作不是刚需，但如果要做「AI 用了多少、改了多少」的统计与信任，这是基础。

### 第二批落地纪要（v0.8.0）

- **B1 适配而非照抄**：studio 的 `validateContinuity` 建在 characters/relations/scenes 结构化
  实体上；本插件没有这些实体（人物=`.md` 卡 + `cast[]`）。改写为本插件真实可判定的信号集，
  另加 studio 没有的两类：**章节索引 vs 磁盘**、**账本自身自洽**（章号超前/同章多值）。
- **死亡判定要排反例**：`不死之身`/`拼死一战`/`死寂`/`生死` 都不是死亡——只做「键名命中 + 死亡词命中 + 反例未命中」三条件。
- **闪回豁免**：细纲或正文开头 400 字里出现「回忆/闪回/梦境/当年」→ 死亡再现降级为警告（studio 的 flashback/dream 语义）。
- **A5 的「默认开」** 通过 C2 的内容门禁实现：默认 enforce，`force:true` 才放行且记审计。
- **算不了的明确不装**：物理硬伤、创意类承诺违背仍归模型+人；内容门禁只做代码能判定的四维。

## 一句话总结

**最该抄的不是功能数量，是三条「判定权」**：
1. **谁批准** → A1（工具层）+ A2（审计留痕）
2. **谁判定质量** → A3/A4/B1（代码算）+ C2（模型补主观）
3. **谁先动笔** → F2（persona 铁律）+ A5（门禁默认开）

其余 15 条都是围绕这三条的外围增强。


### 第三批落地纪要（v0.9.0）

四条解决「**上下文喂什么**」——前两批管「能不能写、谁批准」，这批管「写的时候看得见什么、看不见什么」。

**B3 场景契约**（`lib/scene-contract.js` + `novel_scene`）：契约按章声明
`scene / participants / hidden / settings / forbidden / notes`。
- 省 token：契约在场时 briefing 只注入 `participants` 的人物卡，世界书按 `settings` 白名单取；无契约退回原行为（老书零影响）。
- 悬念保护：`hidden` 人物 ① 档案不进上下文 ② **注入区块连名字都不写**（只说「有 N 人未登场」）
  ③ 正文出现其名 → 内容门禁拒绝落盘（force 可放行并记审计）。

**E3 语言基因卡**（`lib/voice.js`）：六个结构化字段（句长/逻辑/口头禅/绝不说/小动作/语域），
存 `设定/语言基因.json`。briefing 单独注入成区块；`novel_audit voice:true` 核对——
说了自己声明过的「绝不说」= 硬伤，有台词却没一句口头禅 = 提示。

**A3+A4 细纲契约指标**（`lib/gate-metrics.js`）：细纲写 `## 本章必写场景` / `## 本章禁止偏离项`，
代码算 `coverage / drift / missedScenes / bannedHits`，落盘 `novel.json.chapters[n].gate` 可看趋势。
与彼的三处差异：契约段可选（不 fail-closed）、解析不出只提示不阻断、禁项按否定句式三分类
（排除型计偏离度，需求型/条件型不计——避免「写对了反而被拦」）。

**两个真问题（实测踩到，都已修）**：
1. **契约自己泄底**：`notes` 写「X 的真实身份本章不揭」会把名字注入上下文。
   现在双层擦除——渲染层把 scene/forbidden/notes 里的隐藏名替换为「（该人物）」；
   `scrubHiddenNames` 对最终注入的每一节逐行过滤（账本/摘要里的**派生泄漏**一并堵掉），
   删空则整节不注入，被删节尾注记「已屏蔽 N 行」。
2. **门禁判定顺序**：`novel_write_chapter` 的细纲禁项判定原本排在内容门禁之前，
   导致先抛禁项、内容门禁（死人复活/隐藏人物泄底）没机会判。已改为内容门禁 → 细纲契约。

**下一批（第四批·流程与角色）**：E1 队长 + 5 子代理（纯 persona，278 行就能实现）、
F1 九阶段状态机 + PhaseReport、C4 平台审稿（起点/番茄）、C5 敏感自查六类。


### 第四批落地纪要（v0.10.0）

四条解决「**什么时候能写、谁说了算**」。第三批管「写的时候看得见什么」，这批管「准不准写」。

**F1 九阶段状态机**（`lib/phases.js` + `lib/phase-io.js`）：五段扩到九段
（立意→设定→人物→大纲→分卷→细纲→正文→修订→完稿），每段带**入场条件**（纯函数）
与 **PhaseReport**。三个设计取舍：
- **入场条件是「可列出的缺口」而不是布尔**：失败时返回 `missing[]`，模型知道该补什么
  （只说 false 等于没说）。`novel_project phase` 不给 `stage` 就是看板。
- **越级可审计**：force 时不静默放行，被越过的前置阶段一律记 `skipped`，
  PhaseReport 记下当时的缺口数——「跳阶段」本身成了审计事件。
- **老数据零迁移**：旧五段名做别名映射，读写与面板展示三处都认。这一步花的时间比写
  九阶段本身还多——库里没有迁移器，兼容只能靠别名。

**E2 熔断**（`lib/circuit-breaker.js`）：核把这条写在 persona 里，但按本插件的
第一原则「靠模型自觉的约束视同没有」，必须落成状态：
- 计数落 `novel.json.gateFailures`。**驳回路径也要 saveBook**——否则计数活在内存里，
  进程一退就归零，熔断永远数不满（这是实现时踩到的真坑）。
- 三条解除通道都对应「设定被重新校准」这个语义：细纲重批、场景契约更新、force 放行。
  不解成「时间到了自动放行」——那等于没有熔断。

**E1 队长 + 5 子代理**：纯 persona（核只用了 278 行）。落点是三段：
角色分工（世界/剧情/人物/文笔/复核）、通信经济（派单给切片、长文本用路径引用）、
否决权与熔断权（一票否决 + 3 轮终裁 + 熔断后回去重校准）。同时补了「每 3–5 章全局刷新」。

**C4 平台审稿**（`lib/platform-review.js`）：两家口味做成**两张表**而不是一套权重——
起点看结构（2000–4000 字/章末钩子/移动端段长/黄金三章开篇 300 字立冲突/每 3 章爽点），
番茄看抓人（前 1000 字小爽点/前 3 章打脸/段均 ≤150 且对话 ≥25%/憋屈时长 ≤1200 字）。
每条给 `value/target/advice`：不是打分，是改稿清单。复用已有纯函数，零新增模型调用。

**C5 敏感自查**（`lib/censor.js`）：七类，命中给行号 + 摘录 + 改法。
两处刻意设计：
- **未成年红线用邻近共现**（主体词 × 亲密词 100 字内），单出现「小学生」不报警——
  校园文天天有小学生，一刀切等于天天误报，作者会直接关掉这个功能。
- **涉政类不枚举敏感词**，只做语域识别（政体术语/群体事件/情报机构等通用标记），
  命中提示人工复核。文件头写明：启发式预筛，不是合规判定，不是免责工具。

**顺带修掉两个真问题**：
1. `novel_clone_project` 漏复制第三批的 `设定/场景契约.json` 与 `设定/语言基因.json`——
   克隆出一本新书，悬念保护和人物口吻全丢了。已补进复制清单（跨批次回归）。
2. 同上「驳回不落盘」：熔断计数与 `novel.json` 的写入时机不一致。

**下一批（第五批·重资产）**：D1 旁路直调（独立 key 四通道）、D2 并发批量起草、G1 向量索引。
三条都要配 key / 建索引 / 处理流式与错误，建议先各做一个 PoC 再决定是否全量。
